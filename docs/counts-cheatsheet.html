Counts Cheat Sheet

Every fixture slot in Counts has two independent knobs: Catalog Number1–6 builds the part-number string (and can explode a run into multiple cut rows), and Catalog Qty1–6 decides how many of that part to order. Both resolve per fixture instance — the length-aware modes against the Linear Length parameter.

Catalog Number{1–6}
The part string

Static text plus optional length tokens. Length tokens can explode one instance into several Worksheet rows — one per cut length — with the length baked into the SKU.

⊗ mutually exclusive per slot
Catalog Qty{1–6}
How many

One quantity rule per slot — flat counts, multiples, ratios, per-type, or continuous-stock piece counts via N @ft / N @in. Never explodes; the SKU stays fixed and only the quantity scales.

A single slot uses one or the other: a length token in the Catalog Number and a Catalog Qty value on the same slot is a validation error.

Part 1 · Catalog Number

Length tokens

Drop a {…} token into Catalog Number1–Catalog Number6 to stamp each instance's Linear Length into the part number. A bare format produces one row per unique resolved length; a cut-list mode (max / sizes / pool) splits each run into orderable pieces.

Pick a cut mode

max=N Made-to-length

Greedy-splits each instance into N"-sized cuts plus one remainder piece. Every cut is a real ordered length — zero waste.

Use when Vendor cuts to spec: sealed extrusion, factory-finished continuous-run linear, IP-rated tape channel.
sizes=N|N|... Discrete stock, per-instance

Covers each instance with the fewest sticks whose sum ≥ instance length, tie-break least overage. Each instance gets dedicated material — no offcut reuse.

Use when Track with a feed + end-cap kit per cut, sealed-but-cuttable stock, anything where fresh sticks have a meaningful advantage over offcuts.
pool=N|N|... Discrete stock, pooled

Same stock sizes as sizes=, but offcuts are reused across instances. Hardcoded 18" minimum reusable offcut. Typically drops waste from ~25% to ~3–5% on multi-size jobs.

Use when Offcuts are fungible with fresh-stick cut ends: raw aluminum LED channel, raw track without factory-finished ends.

Part 2 · Catalog Qty

Catalog Qty modes

Put a quantity rule in Catalog Qty1–Catalog Qty6 to control the ordered quantity for that slot's part. The input string picks the mode automatically. Leave it blank and the slot just inherits the fixture Count.

Input Mode Computes What it's for
(blank) default Count One per fixture. The normal case — order as many parts as there are fixtures.
N per-fixture Count × N A fixed multiple per fixture: 2 mounting clips, 4 screws, a pair of end caps.
1/N ratio ceil(Count / N) One shared part per N fixtures: one driver per 4 heads, one feed per 6 modules. Rounds up.
N @type per-type N A flat count for the whole type, regardless of fixture count: one controller, one power pack.
N @ft length ceil(ceil(LinearLength × 1.05) / N) Continuous stock N feet long, cut to cover the run, with 5% overage. Tape reels, channel sticks.
N @in length ceil(ceil(LinearLength × 1.05) / (N ÷ 12)) Same as @ft, but stock is given in inches (normalized to feet internally). Use for clip spacing and short stock you naturally measure in inches.

N is a positive number. It must be a whole number for the first four modes; for @ft/@in it may be fractional (stock lengths like 16.40 ft or 21 in are valid). @ft and @in are the same Length mode — only the unit of the number differs, and @in is divided by 12 to feet, so 16.40 @ft and 196.80 @in compute identically.

The Length mode (@ft / @in) in detail

Continuous stock → piece count

N is the stock length — a reel, a channel stick, or a clip interval. State the unit in the keyword: @ft for feet, @in for inches. The run (Linear Length, in feet) is padded by 5% for overage, rounded up to whole feet, then divided by the stock length and rounded up to whole pieces. @in stock is converted to feet (÷ 12) first, so the division is always feet ÷ feet.

Choosing

Length token, or @ft / @in?

Both deal with continuous runs, but they answer different questions. The deciding factor is whether the cut length belongs in the part number or only in the quantity.

Catalog Number · max / sizes / pool
Explode by length

One instance becomes several Worksheet rows, each a distinct SKU with the cut length stamped into the part number. Pricing sees a line per length.

Use when each cut is its own orderable, length-specific item — made-to-spec extrusion, end-capped track kits, finished linear.
Catalog Qty · N @ft / N @in
Scale one SKU

One fixed part number, one row. Only the quantity grows with the run — the number of reels, sticks, or clips needed to cover it.

Use when the stock is a single SKU no matter how much you cut — LED tape reels, generic channel by the stick, mounting clips by spacing.
Reference

Rules

  • Within a Catalog Number token, max, sizes, and pool are mutually exclusive.
  • All max, sizes, and pool values are positive integers in inches, regardless of the display format.
  • Units are explicit, never guessed. Catalog Number cut-list tokens (max/sizes/pool) are always inches; Catalog Qty stock length states its own unit — @ft or @in. There is no unit-less length keyword.
  • A slot cannot carry both a length token (in Catalog Number) and a Catalog Qty value — pick one per slot.
  • N @ft / N @in require the type to have instances with a positive Linear Length; otherwise it's a validation error.
  • Length-aware modes (length tokens and @ft/@in) resolve against each instance's Linear Length; the other Catalog Qty modes resolve against the fixture Count.
  • N is whole-number for N, 1/N, and N @type; N @ft/@in accept fractional stock lengths.
